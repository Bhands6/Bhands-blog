# 部署到阿里云 ECS（blog.bhands.me）

目标服务器：阿里云 `8.163.10.206`（bhands.me 所在的那台，已跑缘分故事屋）。
架构：Caddy（已有，自动 HTTPS）→ `blog-app`（Next.js，127.0.0.1:3000）→ `blog-mysql` / `blog-redis`（compose 内部网络）。

---

## 0. 前置条件

| 项 | 要求 |
|---|---|
| 服务器 | Docker 与 Docker Compose v2 已安装（缘分故事屋在用，应已就绪） |
| 内存 | 2G 内存务必先加 2G swap（见步骤 0），否则 `next build` 可能被 OOM 杀掉 |
| DNS | `blog.bhands.me` → A 记录指向 `8.163.10.206`（bhands.me 已在阿里云接入备案，子域无需再备案） |
| 本地 | Git Bash + Docker Desktop（用于导出数据与本地试构建） |

### 步骤 0 · 服务器初始化（root 执行，只需一次）

```bash
# 加 2G swap（如果 free -h 显示 swap 已 ≥2G 可跳过）
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

# 部署目录
mkdir -p /home/bhands-blog
```

## 1. 上传代码（本机 Git Bash 执行）

⚠️ 国内服务器访问 GitHub 不稳定，**不要在服务器上 git clone**，从本地打包推送：

```bash
cd /f/UE/Bhands-blog
tar --exclude=node_modules --exclude=.next --exclude=.git \
    --exclude=.vercel --exclude=.workbuddy --exclude=.trae \
    --exclude=".env*" --exclude="deploy/data" \
    -czf /tmp/blog-src.tgz .
scp /tmp/blog-src.tgz root@8.163.10.206:/home/bhands-blog/

# 服务器上解压
ssh root@8.163.10.206 "cd /home/bhands-blog && tar -xzf blog-src.tgz"
```

## 2. 配置环境变量

```bash
# 服务器上
cd /home/bhands-blog
cp deploy/env.production.example deploy/env.production
vi deploy/env.production     # 填三组强密码 + JWT_SECRET + CRON_SECRET
chmod 600 deploy/env.production
```

## 3. 启动 MySQL + Redis

```bash
docker compose --env-file deploy/env.production -f docker-compose.prod.yml up -d mysql redis
docker ps   # 等 blog-mysql 变 healthy（约 30 秒）
```

## 4. 迁移数据（本地导出 → 服务器导入）

**本机 Git Bash**（从本地 nexus-mysql 导出全量库，含表结构 + 数据）：

```bash
docker exec nexus-mysql mysqldump -unexus -pnexus123 \
  --default-character-set=utf8mb4 --single-transaction \
  bhands_blog > /tmp/bhands_blog.sql
scp /tmp/bhands_blog.sql root@8.163.10.206:/home/bhands-blog/
```

**服务器**（dump 自带 DROP/CREATE TABLE，导入即完整重建，无需再 db push）：

```bash
docker exec -i blog-mysql mysql -unexus -p'<MYSQL_PASSWORD的值>' \
  --default-character-set=utf8mb4 bhands_blog < /home/bhands-blog/bhands_blog.sql
```

迁完的内容：账号（Bhands / 123）、文章浏览量与点赞、About 页文案、图片。
**Redis 不迁移**（浏览计数在 Redis 的部分会从零开始，MySQL 里的累计值不受影响）。

## 5. 构建并启动应用

```bash
docker compose --env-file deploy/env.production -f docker-compose.prod.yml build app
docker compose --env-file deploy/env.production -f docker-compose.prod.yml up -d app
docker logs -f blog-app        # 看到 Ready 即启动完成（Ctrl+C 退出查看）
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3000/zh   # 期望 200
```

> 构建期 SSG 页面（归档/关于/详情）会连数据库取数据，所以**先迁移数据再 build**，
> 静态页面里才会带上真实内容。之后数据变化靠各写接口的 `revalidatePath` 自动刷新。

## 6. Caddy 反代（bhands.me 那台的 Caddyfile 追加一段）

```
blog.bhands.me {
    reverse_proxy 127.0.0.1:3000
    encode gzip
}
```

重载：`caddy reload --config /etc/caddy/Caddyfile`（或 systemctl reload caddy）。
Caddy 会自动申请并续期 HTTPS 证书。

## 7. crontab（替代 Vercel Cron 的浏览量兜底回写）

```bash
crontab -e
# 每天北京时间 03:30 回写一次（CRON_SECRET 用 deploy/env.production 里的值）
30 3 * * * curl -s -H "Authorization: Bearer <CRON_SECRET>" http://127.0.0.1:3000/api/cron/flush-views > /dev/null
```

## 常见问题

| 现象 | 处理 |
|---|---|
| build 被 OOM 杀死 | 确认 swap 已生效（`free -h`）；仍不足就用本地 `docker build` + `docker save/load` 上传镜像 |
| 构建期报数据库连接失败 | 先 `up -d mysql` 并等 healthy，再 build；确认 env.production 里密码与 compose 一致 |
| 页面 200 但数据为空 | 数据是否已导入（步骤 4）；SSG 页面是否在导入**之后**构建（顺序错了就 `build app` 重来一次） |
| 502 | `docker logs blog-app`；app 未 healthy 时 Caddy 会 502 |
