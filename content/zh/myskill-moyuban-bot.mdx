说实话，这是我做过的**最不正经**的一个项目。

「摸鱼办」是程序员圈子里的固定节目：上班第一件事，先看一眼距离周末、发薪日、下一个假期还有几天，然后把这份"通报"发到评论区，署名「摸鱼办」。

手动算一次两次还行，天天算就有点蠢了。所以我把它做成了两个 Claude Code 的技能——在 Claude Code 里说一句「CSDN」或者「jj」，剩下的它自己做完。

![摸鱼办的自动化链路：触发词 → 读 Cookie → 脚本算日期 → 模型写内容 → 组装 → 发布](/blog/myskill/pipeline.png)

## 一、发出来长这样

在 CSDN 极客日报最新文章下的评论，下面是**用今天的真实日期跑出来的**内容：

```
各位C友们，下午好！
今天2026年10月12号星期一！
摸鱼办在此温馨提醒您：

🥳 周末
距离周末双休还有 ⏳ 5 天
距离周末单休还有 ⏳ 6 天

💴 工资
距离15号发薪日还有 ⏳ 3 天
距离20号发薪日还有 ⏳ 8 天
距离25号发薪日还有 ⏳ 13 天
距离31号发薪日还有 ⏳ 19 天

🎉 节假日

摸鱼办温馨提示：
{语录}
{冷笑话}

——摸鱼办 敬上（用Claude code自动发布)
```

掘金那边发的是沸点，比 CSDN 多一段「今日宜忌 + 鸡汤」——这两样是从掘金签到页上直接抓的。

注意 `{语录}` 和 `{冷笑话}` 那两行是**留空的**。它们不是脚本生成的，是每次让 Claude 现写的：一句十几二十字的早安语录，加一个程序员向的冷笑话，而且要求不能和上次重复。

## 二、这个项目真正的设计点

代码量很小，整个仓库 21KB。但里面有一条分工我觉得值得单独记下来。

**如果让模型自己算「距离周末还有几天」，它是会算错的。**

尤其是跨月、跨年、闰年的时候。日期计算这件事模型就是不可靠，而且同一个问题每次问还可能给你不同答案——它是在"生成"一个看起来合理的数字，不是在"计算"。

所以这个项目的分工是这样的：

| 谁来做 | 做什么 | 为什么 |
|---|---|---|
| **Python 脚本** | 算周末 / 发薪日 / 节假日天数 | 必须有确定答案，且每次调用都一样 |
| **Claude** | 写早安语录、编冷笑话、组装内容 | 需要"人味"，脚本写不出来 |

`shared/dates.py` 只干一件事：把「现在几点」变成一份 JSON。而 `skill.md` 里是明确写着**「使用脚本计算」**的，不是让模型自己心算。

这条界线划在哪儿，我觉得是这个项目里唯一需要动脑子的地方——**凡是"答错了会被人当场看出来"的，都得是代码；凡是"答得不一样反而更好"的，才交给模型。**

## 三、「距离多少天」是怎么算的

![距离周末天数计算规则表：星期一到星期日分别距离周六周日几天，含周六 18:00 的例外](/blog/myskill/date-rules.png)

图上那些数字不是我填的，是**直接跑 `shared/dates.py` 得出来的**。几个规则挺有意思：

- **周六过了 18:00，距周末直接变成 7 天** —— 这周的双休眼看就过完了，该开始盼下周六了。这个特判让周六晚上打开时不会还在显示「还有 0 天」。
- **发薪日是 1 / 5 / 10 / 15 / 20 / 25 号，外加每月最后一天** —— 已经过去的自动顺延到下个月。所以今天（10 月 12 号）跑出来会看到「距离 1 号发薪日还有 20 天」，那其实是 11 月 1 号。
- **时段问候**按小时切：6-11「早上好」、11-14「中午好」、14-18「下午好」、18-24「晚上好」、0-6「夜深了」。

顺便说一个**现在的真实情况**：如果你现在跑它，「节假日」那一栏是**空的**。

因为 `HOLIDAYS` 字典里只配了 2026 年的端午、中秋、国庆——而今天已经 10 月 12 号了，全过完了。README 里那句「节假日数据需要每年手动更新」不是客套话，是真的会变成空白。明年得记得把 2027 的假期加进去。

> 硬编码节假日的取舍很清楚：**不依赖任何外部服务，代价是每年手动改一次**。要做得"正规"可以接节假日 API，但那就多了一个会挂、会限流、会改字段的依赖——为了一个一年用一次的功能，不划算。

## 四、两个平台的坑

### Cookie 是唯一的凭据

两个平台都要浏览器登录 cookie 才能发文，分别存在 `~/.csdn_cookie.txt` 和 `~/.juejin_cookie.txt`。这两个文件在 `.gitignore` 里排除了，不会进仓库——这种东西进了仓库，等于把账号送人。

Cookie 会过期，过期了就重新取一次。

### 掘金做了三层

| 层级 | 干什么 |
|---|---|
| API 直接发沸点 | 首选路径 |
| 抓签到页 | 拿「每日宜忌 + 鸡汤」 |
| Playwright 开浏览器 | API 方式失败时的兜底 |

第三层是纯兜底，专门为「API 挂了至少功能还在」准备的。多写一个 `juejin_playwright.py` 看起来是浪费，但它把"这个功能今天能不能用"从"看官方接口心情"变成了"基本能"。

### 发出去不等于立刻可见

掘金沸点发完要过审核，不会马上显示。不知道这一点的话，发完去看发现没有，会以为失败了然后重复发。

## 五、一个 Claude Code skill 长什么样

拆开看其实很简单，**一份说明 + 一个脚本**：

```
MySkill/
├── shared/
│   └── dates.py                  # 公共日期计算
├── csdn-comment/
│   ├── skill.md                  # 触发词 + 执行流程
│   └── scripts/csdn_comment.py
└── juejin-comment/
    ├── skill.md
    └── scripts/
        ├── juejin_comment.py     # 发沸点
        ├── juejin_checkin.py     # 抓宜忌和鸡汤
        └── juejin_playwright.py  # 浏览器兜底
```

`skill.md` 顶部的 frontmatter 决定它什么时候被唤起：

```yaml
---
name: csdn-comment
description: 在CSDN极客日报最新文章下发布摸鱼办早安评论。当用户说"CSDN"、
  "发CSDN评论"、"csdn评论"、"极客日报评论"、"摸鱼办"、"早安评论"时触发。
---
```

**description 里列的那些词就是触发词**——不用记任何命令，说到就会用。往下是一步一步的执行流程（Step 1 读 Cookie、Step 2 算日期、Step 3 写语录、Step 3.5 编笑话……），本质上是写给模型看的作业指导书。

我越来越觉得，这类东西的价值不在代码量上，而在于**把"什么时候做、按什么步骤做、哪一步交给谁"写清楚了**。模型不缺能力，缺的是可靠的过程。

## 六、装起来用

```bash
cd ~/.claude/skills
git clone https://github.com/Bhands6/MySkill.git
ln -s MySkill/csdn-comment csdn-comment
ln -s MySkill/juejin-comment juejin-comment
```

配好 cookie 之后，在 Claude Code 里说「CSDN」或「jj」就行了。

不想走 Claude Code 也可以直接调脚本：

```bash
# 只看日期算出来是什么
python csdn-comment/scripts/csdn_comment.py --action dates

# 直接发一条沸点
python juejin-comment/scripts/juejin_comment.py --action post_pin \
  --cookie "$(cat ~/.juejin_cookie.txt)" \
  --content "沸点内容" \
  --topic-id 6824710203301167112
```

圈子 ID `6824710203301167112` 是「上班摸鱼」。
