## 一、迁移不是复制粘贴

桌面版是 Electron——本质上是一个打包好的 Chromium 加一堆 Node.js 权限。搬到浏览器里，有些东西直接就不能用了：

| 桌面版能做的 | 浏览器里 |
|---|---|
| 读写本地文件、扫描本地音乐库 | 只能用户主动选择文件 |
| 想开哪个端口开哪个端口 | 只有 HTTP |
| 直接 fetch 任意第三方接口 | 跨域（CORS）直接拦掉 |
| 常驻后台、托盘、桌面歌词独立窗口 | 标签页关了就没了 |

所以「迁移」的真实含义是：**把不能做的砍掉，把能做的换个做法**。

砍掉的是本地音乐库扫描、托盘、独立桌面歌词窗口。

换做法的，最关键的一条是：**后端必须存在**。

## 二、为什么非得有台服务器

网易云的接口不允许浏览器直接调（CORS 只是最表层的问题，还有签名、Cookie 会话、音源解析一大堆）。

所以后端做三件事：

1. **代理网易云 API**，把登录态 Cookie 存在服务端，浏览器只拿一个会话标识
2. **解析音源**，拿到真正可播的直链
3. **在沙盒里跑音源脚本**——这条后面细说

前端 React 19 + TypeScript + Vite + Zustand + Three.js，后端 Node.js + Fastify。都是很常规的选型，没什么好炫的，好处是遇到问题搜得到答案。

## 四、一个预设推翻四遍

这段我本来不想写，因为它看起来不太"高效"。但它大概是这个项目里最真实的部分。

光「心跳」这一个预设，提交记录是这样的：

```
心跳v2   修上下尖刺、柔化核心、内心星尘填充
心跳v3   尖点密度重投治本——主体/星尘按 |hx| 概率重投
心跳v3.5 撤销 v3 密度重投（用户否决）
         —— 凹口细刺与底尖亮尖是心形特征，须保留，恢复 v2 形态
心跳v4   曲线主体恢复原版忠实移植（锐利霓虹心）
         撤销 v2 柔化套件；唯一保留星尘填充
```

绕了一圈，最后回到原版。

我在 v3 的时候想做的是"治本"——用概率重投把那些不好看的尖点从根上消掉。改完密度是均匀了，但**心形最好看的特征也被磨平了**：凹口那几根细刺、底尖那个亮尖，恰恰是它看起来像心脏而不是像水滴的原因。

所以下一版把它全部撤销，只留下 v2 里那个还不错的星尘填充。

这件事的教训不是"别改"，而是：**在几何/视觉这种地方，「更均匀」「更数学正确」经常不等于「更好看」**。改之前得先想清楚你到底想保住哪个特征，而不是先动手再判断。

## 五、小带宽服务器：让音频别从我家过

页面能跑之后我以为最难的过去了。真正麻烦的是带宽。

服务器带宽很小——小到如果让它代理音频流量，一个人听歌就能把出口占满，第二个人进来就开始转圈。

解法是**不给它代理**：`/api/music/stream` 拿到网易的 https 直链后，直接返回 **302 重定向**，让浏览器去 CDN 取音频。服务器只负责握手和解析，一个字节的音频都不转发。

```env
# 默认行为：302 直连，省服务器带宽
STREAM_DIRECT_REDIRECT=on

# 需要恢复服务器代理模式时打开（比如直链不可用时）
STREAM_DIRECT_REDIRECT=off
```

页面、接口、歌词这些走服务器的流量很小，真正的大头（音频）全绕开了。这个开关默认开着，但保留关闭的能力——因为直链有时效性和可用性问题，得有回退路径。

## 六、在沙盒里跑陌生人写的脚本

播放器支持上传 LX 格式的音源脚本。

这类脚本是**别人写的代码**，功能就是解析出音频直链。直接 `eval` 等于把服务器交出去。所以扔进 `worker_threads` + `vm` 沙盒里跑：

- 一次性解析执行，**不落盘留存**
- 跑在独立 worker 里，崩了不影响主进程
- 只有管理员能上传
- 内置音源随服务自动加载，不可删除

顺便一个设计上的取舍：**自定义音源只接"拿到可播地址"这一件事**，不让它参与播放控制逻辑。脚本能做的事越窄，能出的事就越少。

## 七、GLSL ES 1.00 的几个坑

写粒子着色器有一些反直觉的限制，这些在前端是查不到答案的，只能撞一遍：

- **`pow()` 的底数不能是负数**。浮点误差会让本该是 0 的值变成 -0.0000001，然后整个画面变成一片黑或 NaN。所有 `pow(base, exp)` 的 `base` 都得用 `clamp` 包起来
- **没有 `sin³` 这种写法**，得老老实实连乘
- **音频联动只接观感量**——亮度、缩放可以接，位置量不要接。位置跟着音频跳，帧率一抖就是满屏抖动，看起来像 bug 而不是律动

还有一条不是 GLSL 但同样气的：**测试必须在 `apps/web` / `apps/server` 目录下跑**。在仓库根目录跑会报一堆 jsdom 的错，看起来像配置炸了，其实只是 vitest 找不到配置。

现在两端一共 **237 个测试用例**，加上 oxlint。

## 八、跑起来 & 部署

前端构建成静态资源，由后端**单端口 6628** 一起托管（省掉一套静态服务器）。

```bash
npm install
npm run build
npm start          # http://localhost:6628
```

开发模式前后端并行：

```bash
npm run dev        # 前端 5173 / 后端 6628
```

Windows 上还有一键脚本 `deploy-local.bat`，双击就行——装依赖、构建、起服务、开浏览器一条龙。

生产是 Docker Compose + Caddy（自动 HTTPS）。改过 `Caddyfile` 记得重启 caddy 容器，不然配置不生效——这个坑我踩过。

另外做了 PWA，可以像 App 一样装到桌面和手机上；移动端也做了适配。

## 九、写在最后

桌面版和网页版现在是两个东西：桌面版更适合当成每天用的播放器，网页版更适合"随手打开听一首"和分享给别人。
